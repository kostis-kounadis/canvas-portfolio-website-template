# Canvas Portfolio → Commercial Template: Implementation Plan

> **Goal**: Transform the existing `_portfolio_v7_DEPLOYED` codebase into a fully functional, commercially distributable, highly customisable portfolio template — complete with a Node.js-powered GUI setup tool, expanded view modes, visual effects, and clear documentation. The template remains a **static website** deployable for free on Cloudflare Pages or Netlify.

---

## Current Codebase Snapshot

| File | Role |
|---|---|
| `index.html` | Minimal shell; nav/stage/footer injected by JS |
| `main.js` (1,726 lines) | All interaction: scatter, drag, zoom, pan, layout modes (random / rows / stacks), info overlay, preloader, categories, mobile slideshow |
| `style.css` (754 lines) | Full design system using CSS variables (`--text-colour`, `--bg-colour`, `--ui-text-size`) |
| `data.js` | `window.mediaItems` array (auto-generated by build script) |
| `setup.md` | YAML front-matter config + info body text (fetched at runtime) |
| `admin/generate-data.js` | Node.js: scans `assets/images/`, reads dimensions via `sharp`, writes `data.js` |

**Three layout modes**: random scatter, rows, stacks.

### Phase 2 — UI Modules Positioning System (8-Zone)
*Model: **Claude Sonnet 4.6 (Thinking)***

Currently all UI positions are hardcoded in CSS (`nav` = top, `#category-panel` = middle-left, etc.). This phase makes all non-zoom modules data-driven via the 8-zone grouping system.

**Zone definitions (8 zones + zoom special)**:
- `top-left`, `top-center`, `top-right`
- `middle-left`, `middle-right`
- `bottom-left`, `bottom-center`, `bottom-right`
- **Zoom**: excluded from zone system — always pinned full-width at bottom (flex row, space-between), as it is now. Visibility only is configurable.

**Grouping logic**: modules sharing the same zone string are rendered inside a single shared container element (`flex-direction: column`, `gap: 4px`). This creates the "stacked top-to-bottom" behaviour described. Modules in different zones each get their own container.

#### [MODIFY] `style.css`
- Remove all hardcoded module positions
- Add 8 zone container classes (e.g. `.zone-top-left { position: fixed; top: 32px; left: 32px; }`) with `mix-blend-mode: difference` inherited from config
- Zone containers are `display: flex; flex-direction: column; align-items: flex-start/center/flex-end` (aligned to match their grid edge)
- `pointer-events: none` on containers, `pointer-events: auto` re-enabled on interactive children

#### [MODIFY] `main.js`
- New `buildZoneContainers()`: creates 8 `<div>` zone elements, added to `<body>`
- Updated `buildNav()`, `buildCategoryPanel()`, `buildLayoutPanel()`: each reads `config.ui.modules[name].position` and appends into the matching zone container
- Zoom: `buildZoomControls()` always appends to `<footer>` as before

> [!NOTE]
> v2 feature branch `feature/gui-drag-modules` will add visual drag-and-drop positioning inside the GUI, using this same zone infrastructure as a foundation.

### Phase 3 — Theme & Visual Customisation System
*Model: **Claude Sonnet 4.6 (Thinking)***

#### [MODIFY] `style.css`
Extended CSS variables:

```css
:root {
  --bg-colour: #f7f5f0;
  --text-colour: #ffff00;
  --ui-text-size: 18px;
  --font-family: "JetBrains Mono", monospace;
  --noise-opacity: 0;
  --shadow-opacity: 0.06;
  --shadow-blur: 30px;
  --shadow-color: rgba(0,0,0,0.06);
}
```

**Background effect system** (5 presets, pure CSS — class toggled by JS from config):

| Class on `<body>` | Effect | CSS technique |
|---|---|---|
| `bg-solid` | Solid colour (default) | `background-color: var(--bg-colour)` |
| `bg-gradient-static` | Two-colour gradient | `linear-gradient(135deg, var(--bg-from), var(--bg-to))` |
| `bg-gradient-animated` | Slow-moving gradient | `background-size: 400% 400%` + `@keyframes bg-shift` (30s ease infinite) |
| `bg-blob-mesh` | Two blurred radial blobs drifting | `::before`/`::after` with `filter: blur(80px)` + `@keyframes drift` (25s alternate) |
| `bg-noise` | Grain only | Combines with any of the above via `body::before` SVG filter |

**Noise/grain implementation** (research-confirmed best approach):
- Inline `<svg style="display:none">` with `<feTurbulence type="fractalNoise" baseFrequency="0.65" numOctaves="3" stitchTiles="stitch">` injected once into `<body>` by JS if grain is enabled
- `body::before` with `filter: url(#grain); opacity: var(--noise-opacity); position:fixed; inset:0; pointer-events:none; z-index:9999`

**Text animation options** (opt-in CSS class on nav/UI elements):

| Class | Effect | Compatibility |
|---|---|---|
| `text-fx-none` | Default (no animation) | All |
| `text-fx-color-cycle` | `@keyframes` slow colour shift | All |
| `text-fx-gradient` | `background-clip: text` animated gradient | Chrome/Edge/Safari |
| `text-fx-hue-rotate` | CSS `@property --hue` + `conic-gradient` | Chromium-only, graceful fallback |

All animations respect `@media (prefers-reduced-motion: reduce) { animation: none }`.

**Image shadow** via CSS variables on `.media-item`:
```css
.media-item {
  box-shadow: 0 var(--shadow-blur) calc(var(--shadow-blur) * 2) var(--shadow-color);
}
body.no-shadow .media-item { box-shadow: none; }
```

#### [MODIFY] `main.js`
- New `applyTheme(config)` function: sets all CSS variables, toggles body classes for background effect, text animation, shadow

### Phase 5 — Image Effects System
*Model: **Claude Sonnet 4.6 (Thinking)***

Both gallery mode (multi-sticky) and spotlight mode (single-sticky) are implemented. All effects work in **random, rows, and stacks** layout modes.

#### Initial State Modes (`config.imageEffects.initialState`):

| Value | All images start as | CSS applied to `.media-item img` |
|---|---|---|
| `colour` | Full colour (default) | None |
| `desaturated` | Greyscale | `filter: grayscale(1)` |
| `duotone` | Greyscale + hue tint | `filter: grayscale(1) sepia(1) hue-rotate(var(--duotone-hue)) saturate(var(--duotone-sat))` |

#### Interaction Layer:

| Config key | Value | Behaviour |
|---|---|---|
| `hoverReveal` | `true` | Hovering a desaturated/duotone image reveals full colour |
| `clickMode` | `"gallery"` | Clicking adds `.is-coloured` (sticky); multiple images accumulate |
| `clickMode` | `"spotlight"` | Clicking adds `.is-coloured` to this image, removes from all others |
| `blurOthersOnClick` | `true` | Clicking any image adds `.is-blurred` to all siblings |

#### [MODIFY] `style.css`
```css
body.fx-desaturated .media-item img { filter: grayscale(1); transition: filter 0.4s ease; }
body.fx-duotone .media-item img { filter: grayscale(1) sepia(1) hue-rotate(var(--duotone-hue,200deg)) saturate(var(--duotone-sat,2)); transition: filter 0.4s ease; }

body[class*="fx-"] .media-item:hover img,
body[class*="fx-"] .media-item.is-coloured img { filter: none; }

.media-item.is-blurred img { filter: blur(6px) opacity(0.4); transition: filter 0.3s ease; }
```

#### [MODIFY] `main.js`
- `applyImageEffects(config)`: sets body classes and CSS vars from config
- `handleItemClick(el)`: new unified click handler that respects `clickMode`, `blurOthersOnClick`
- Integrated into existing `el.addEventListener("mousedown", ...)` in `createMediaElement()`

### Phase 6 — Image Click / Lightbox + Canvas Expand
*Model: **Claude Sonnet 4.6 (Thinking)***

Both modes independently configurable. Either, neither, or both can be active simultaneously.

#### Lightbox (`config.imageClick.lightbox.enabled`)
- Click image → `<div id="lightbox">` covers viewport (`position:fixed; inset:0; z-index:9000`)
- Backdrop effect: `darken` (rgba overlay), `blur` (backdrop-filter), or `none`
- Image displayed at max natural size within viewport
- ESC to close, arrow keys to navigate to next/previous image
- Close button `[×]` top-right

#### Canvas Expand (`config.imageClick.canvasExpand.enabled`)
- Click image → `setZoom()` animates canvas to frame the clicked image centred in viewport
- Clicking a second image: previous returns to its original size/position, new one zooms to
- Implementation: store `expandedEl` reference, on new click call `resetView()` for previous then zoom to new
- Works alongside dragging (clicking without moving = expand, dragging = drag)

#### Conflict handling
- If both are enabled: lightbox takes priority on direct click; canvas expand activates on double-click
- Configurable via `config.imageClick.triggerMode: "single" | "double"`

### Phase 11 — GUI Setup Tool (Node.js Server)
*Model: **Claude Sonnet 4.6 (Thinking)*** (complex, high effort)

The GUI replaces the `setup.md` manual-edit workflow entirely.

#### Architecture: Tiny Node.js server

**Why Node.js over File System Access API (after decision)**:
- Works in all browsers including Safari and Firefox
- Reads/writes `config.json` silently without browser permission dialogs
- Can also trigger the `generate-data.js` build script from within the GUI ("Rebuild Site" button)
- Aligns with existing `admin/` Node.js infrastructure

#### New files:
- **`admin/setup-server.js`** — ~80 lines, vanilla Node.js (`http` + `fs` + `path`, no Express)
  - `GET /api/config` — reads and returns `config.json`
  - `POST /api/config` — receives and writes `config.json`
  - `POST /api/build` — runs `generate-data.js` as a child process
  - Serves static files from `setup/` directory
  - Serves portfolio files from root (for live preview)
- **`setup/index.html`** — the GUI single-page app
- **`setup/setup.css`** — GUI styling
- **`setup/setup.js`** — GUI logic
- **`start-setup.command`** (macOS double-clickable) — runs `node admin/setup-server.js` and opens browser
- **`start-setup.sh`** (Linux/cross-platform alternative)
- **`README-SETUP.md`** — platform-specific setup instructions (macOS Homebrew, Windows nvm, Linux apt)

#### Platform setup instructions cover:
1. **macOS**: Install Homebrew → `brew install node` → double-click `start-setup.command`
2. **Windows**: Download Node.js installer from nodejs.org → `node admin/setup-server.js` in cmd
3. **Linux**: `sudo apt install nodejs` → `node admin/setup-server.js`

All three platforms: browser auto-opens to `http://localhost:3000/setup/`

#### GUI Architecture

**Visual design**:
- Dark premium aesthetic (distinct from the portfolio)
- Left sidebar (tabbed navigation, ~280px)
- Right panel: live iframe preview of the actual `index.html` portfolio
- Changes are instantly hot-reloaded into the preview iframe via `postMessage` (no page reload)
- A sticky "Save" button writes `config.json` to disk; "Rebuild Site" runs the build script

**Hot-reload mechanism**:
- `setup.js` listens for form changes → serialises to `config` object → `previewIframe.contentWindow.postMessage({ type: 'config-update', config }, '*')`
- `main.js` exposes `window.applyConfig(config)` which re-runs `applyTheme()`, `buildZoneContainers()`, etc. without page reload
